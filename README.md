# Twinline — цифровой двойник предприятия и 3D-тур

Рабочий прототип для студенческого хакатона «Цифровой двойник предприятия и 3D-туры по производству». Веб-система моделирует производственную линию, находит узкие места, сравнивает сценарии изменений и проводит интерактивную 3D-экскурсию, где каждый объект связан с этапом процесса и рассчитанной метрикой.

> **Все данные демонстрационные.** Предприятие вымышленное, показатели синтетические, но внутренне согласованные: их вычисляет одна и та же модель линии. Интеграций с ERP, MES и 1С нет (по ТЗ).

## Быстрый старт

Требуется Node.js 22.18+ (сервер использует встроенные SQLite и запуск TypeScript без сборки; проверено на Node 26).

```bash
npm install
npm run dev
```

Команда запускает сервер авторизации (http://127.0.0.1:3001) и фронтенд (http://127.0.0.1:5173). Откройте http://127.0.0.1:5173.

| Учётная запись | Логин / пароль | Доступ |
|---|---|---|
| Руководитель производства | `manager` / `demo` | Все разделы и управление пользователями |
| Гость экскурсии | `guest` / `tour` | Только 3D-тур, без финансовых показателей |

Демо-учётки создаются при первом запуске; на экране входа есть кнопки быстрого входа. Кроме них работает **регистрация**: новый пользователь получает роль «Гость экскурсии», полный доступ выдаёт руководитель в разделе «Пользователи».

## Авторизация

Настоящая серверная авторизация (`server/`): Node.js + Express, база SQLite (`server/data/twinline.db`, создаётся автоматически).

- пароли хранятся только в виде хеша scrypt с уникальной солью;
- сессия — случайный токен в cookie `HttpOnly` + `SameSite=Lax` на 12 часов, в базе хранится только его хеш;
- роли проверяются сервером на каждом запросе, смена роли и удаление пользователя действуют сразу;
- защита от перебора (5 попыток → блокировка на 15 минут), от CSRF (проверка Origin) и от потери последнего руководителя;
- смена пароля в меню пользователя завершает остальные сессии;
- собираются только логин и пароль — без ФИО и контактов (152-ФЗ).

Подробности и API — в [`docs/02-architecture.md`](docs/02-architecture.md#29-авторизация-и-персональные-данные).

## Команды

```bash
npm run test        # 40 тестов: движок расчёта, хранилище, сервер авторизации
npm run typecheck   # проверка типов TypeScript (фронтенд и сервер)
npm run build       # сборка фронтенда в dist/
npm start           # один процесс: API + собранный фронтенд на http://127.0.0.1:3001
```

Переменные окружения сервера: `TWINLINE_PORT`, `TWINLINE_HOST`, `TWINLINE_DB` (путь к базе), `COOKIE_SECURE=1` (за HTTPS), `TWINLINE_SEED_DEMO=0` (не создавать демо-учётки).

## Что внутри

| Раздел | Маршрут | Возможности |
|---|---|---|
| Обзор производства | `/` | Состояние линии одной фразой, главная цифра выпуска и живая мнемосхема (клик по участку → двойник), подсказки при первом входе (повтор — «Как пользоваться» в меню), KPI с трендами, динамика выпуска с событиями, узкие места с рассчитанными рекомендациями, таблица участков, последние расчёты |
| Цифровой двойник | `/twin` | Мнемосхема на React Flow: поток, очереди, узкое место; слои «загрузка / ожидание / стоимость»; паспорт участка; списочный вид для телефона |
| Сценарии | `/scenarios` | Редактор нагрузки и параметров участков (ресурсы, скорость, время операции, ставка), расчёт, сравнение с базой, выводы, сохранение / дублирование / удаление |
| Аналитика | `/analytics` | Мощность и факт, загрузка, структура времени цикла, накопление очередей, структура затрат, чувствительность «±1 ресурс», сравнение всех сценариев |
| 3D-тур | `/tour` | Цех на Three.js: зоны участков, метки точек интереса, маршрут экскурсии, живые метрики и кейсы, переходы в двойник и аналитику; 2D-план без WebGL |

Путь руководителя: обзор → узкое место → мнемосхема → «Изменить» → параметры → «Рассчитать» → сравнение → «На схеме» → тот же участок в 3D-туре. Подробный сценарий показа — в [`docs/07-demo-script.md`](docs/07-demo-script.md).

## Модель расчёта

Аналитическая модель последовательной линии (теория очередей), без случайных чисел:

- мощность участка `μ = c · 60 · скорость · готовность / t`;
- поток по маршруту, перегрузка при `λ > μ` с ростом задела;
- ожидание в очереди — формула G/G/c Кингмана–Сакасегавы с передачей вариации между участками;
- время цикла, НЗП (закон Литтла), загрузка, простой, затраты и себестоимость.

Формулы — в [`docs/02-architecture.md`](docs/02-architecture.md#24-метод-расчёта), код — в `src/domain/simulation`.

## Структура проекта

```
docs/                     требования, архитектура, модель данных, BPMN/UML/ER, карта точек интереса, тесты, демо
src/
  config/app.ts           название продукта, пороги статусов, параметры модели
  data/demo/              ВСЕ демонстрационные данные (предприятие, история, сценарии, 3D-тур)
  domain/                 типы, движок расчёта, метрики, выводы, форматирование
  store/                  Zustand: текущий пользователь, сценарии и журнал прогонов, уведомления
  lib/api.ts              клиент HTTP API
  components/             дизайн-система (ui), оболочка (layout), графики (charts)
  features/               разделы: auth, dashboard, twin, scenarios, analytics, tour, users
server/                   сервер авторизации: app.ts (API), db.ts (SQLite), sessions, passwords, тесты
```

## Замена демо-данных

Интерфейс читает данные только через типы `src/domain/types.ts`. Чтобы подставить реальное предприятие, замените файлы в `src/data/demo`: `enterprise.ts` (участки и текущие параметры), `history.ts` (ряды нагрузки и готовности), `tour.ts` (планировка, точки интереса, кейсы). Подробно — [`docs/03-data-model.md`](docs/03-data-model.md#35-как-заменить-демо-данные-реальными).
