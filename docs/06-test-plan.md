# 6. План тестирования

## 6.1. Автоматические проверки

| Команда | Что проверяет |
|---|---|
| `npm run typecheck` | Типизация TypeScript (strict) |
| `npm run test` | Модульные тесты (Vitest): движок `src/domain/simulation/engine.test.ts`, хранилище `src/store/persistence.test.ts`, сервер авторизации `server/app.test.ts` — 40 тестов |
| `npm run build` | Сборка production-бандла |

Модульные тесты движка:

| Группа | Проверка |
|---|---|
| Формулы очередей | Ожидание растёт с загрузкой; 0 без нагрузки; для M/M/1 совпадает с точным решением ρ/(1−ρ)·t; выходная вариация при ρ = 1 равна вариации обслуживания |
| Базовый режим | Ограничение — механообработка (статус «Перегрузка»), ОТК в риске, упаковка недогружена; мощность = c·60·скорость·готовность/t; выпуск = нагрузка × выход годных; время цикла = сумма составляющих; себестоимость включает материал; последний день истории = базовый сценарий |
| Монотонность | +1 ресурс → загрузка ↓, цикл ↓; +1 ОЦ переносит ограничение на ОТК и увеличивает затраты; нагрузка ↑ → загрузка всех участков ↑; скорость ↑ → время и загрузка ↓; ставка ресурса ↑ → затраты растут линейно; детерминированность |
| Перегрузка | Выпуск ограничен мощностью, задел растёт со скоростью λ−μ, есть недовыпуск; очередь растёт в течение суток; комплексный сценарий устраняет перегрузку |
| Сравнение | Направление «лучше/хуже» учитывает смысл метрики; база vs база — без изменений |
| Чувствительность | Нельзя убрать единственный ресурс; +1 ресурс на узком месте сокращает цикл |
| Сервер авторизации | Хеши паролей с уникальной солью; парольная политика; 401 без сессии; вход ставит HttpOnly + SameSite cookie; блокировка после 5 неудач; регистрация даёт роль «гость», дубликат логина — 409; выход удаляет сессию; чужой Origin — 403; гость не видит пользователей; смена роли действует сразу; нельзя менять свою роль и удалять себя; удаление завершает сессии; смена пароля |
| Хранилище | Корректные сценарии восстанавливаются; повреждённые и недопустимые отбрасываются с флагом восстановления; подменённый «базовый» игнорируется; неизвестный активный сценарий заменяется базовым |

## 6.2. Ручные тест-кейсы

| ID | Сценарий | Шаги | Ожидаемый результат |
|---|---|---|---|
| ТК-01 | Вход руководителя | `/login` → «Руководитель производства» | Открывается обзор; в меню 5 разделов |
| ТК-02 | Вход гостя и ограничение доступа | Войти как гость; открыть `/`, `/twin` вручную | Перенаправление в `/tour`; в карточках нет стоимости и ссылок на двойник |
| ТК-03 | Ошибка входа | Неверный пароль; затем 5 неудачных попыток подряд | Сообщение у поля; после пятой — блокировка на 15 минут |
| ТК-04 | Обзор показывает перегрузку | Открыть обзор | Баннер «Линия работает с ограничением», У-03 98 %, «Участки с перегрузкой: 1», рекомендация «+1 обрабатывающий центр…» |
| ТК-05 | Переход к участку | Клик по сегменту У-03 в полосе процесса | `/twin?stage=machining`, открыт паспорт, узел подсвечен, схема перекадрирована |
| ТК-06 | Расчёт сценария | Обзор → «Смоделировать» у У-03 → «Рассчитать» | Ресурсы ОЦ = 5 подсвечены; цикл 2 ч 16 мин → 1 ч 20 мин, выпуск без изменений, себестоимость +3,5 %, ограничение смещается на ОТК; уведомление с временем расчёта |
| ТК-07 | Сохранение сценария | После ТК-06 «Сохранить как новый» → ввести имя → перезагрузить страницу | Сценарий в группе «Мои сценарии», параметры и результат сохранились |
| ТК-08 | Удаление с подтверждением | Открыть свой сценарий → «Удалить» | Диалог подтверждения; после подтверждения сценарий исчезает, открывается базовый |
| ТК-09 | Защита несохранённых изменений | Изменить параметр → перейти в «Обзор» | Диалог «Есть несохранённые изменения»; «Отмена» оставляет на странице |
| ТК-10 | Устаревший результат | Рассчитать → изменить параметр | Плашка «результаты устарели», кнопка «Пересчитать» |
| ТК-11 | Тур → процесс → метрика | `/tour` → метка 4 → «Процесс» → «Метрики» | Карточка с метриками У-03 и кейсом SMED; переход на мнемосхему с паспортом; аналитика с выделенным У-03 |
| ТК-12 | Двойник → тур | В паспорте участка «В 3D» | Камера облетает к участку, открыта карточка той же точки |
| ТК-13 | Сценарий в туре | Сценарии → «+1 обрабатывающий центр» → «На схеме» → 3D-тур | В цехе 5 ОЦ (новый с акцентной полосой), колонны на У-03 зелёные |
| ТК-14 | Маршрут экскурсии | Режим «Маршрут» → «Далее» ×6 | Последовательный облёт 7 остановок, счётчик 1/7 … 7/7 |
| ТК-15 | Адаптивность | Ширина 375, 768, 1440 px | Нижняя панель / рейка / боковое меню; на телефоне мнемосхема в виде списка, детали — нижний лист; нет горизонтальной прокрутки страницы |
| ТК-16 | Таблица вместо графика | В аналитике переключить «Таблица» | Те же данные в табличном виде |
| ТК-17 | Неизвестный участок в URL | `/twin?stage=abc` | Предупреждение «Участок не найден», кнопка «Сбросить» |
| ТК-18 | Повреждённое хранилище | В DevTools записать мусор в `twinline.scenarios`, перезагрузить | Уведомление о восстановлении, приложение работает с демо-сценариями |
| ТК-19 | Нет WebGL | Отключить WebGL в браузере, открыть тур | Плашка о недоступности 3D, 2D-план с точками интереса и рабочими карточками |
| ТК-20 | Клавиатура | Пройти Tab-ом обзор, сценарии, мнемосхему (вид «Список») | Видимый фокус, все действия доступны, диалоги закрываются Esc |
| ТК-22 | Регистрация | «Регистрация» → короткий пароль → затем корректный | Ошибка политики паролей; после исправления — вход с ролью «Гость», доступен только тур |
| ТК-23 | Выдача прав | Руководитель → «Пользователи» → роль нового пользователя «Руководитель»; у пользователя вернуться на вкладку | Уведомление «Роль изменена»; у пользователя появляются все разделы без повторного входа |
| ТК-24 | Сессия | Перезагрузить страницу; выйти; открыть `/users` | После перезагрузки вход сохраняется; после выхода — перенаправление на вход |
| ТК-21 | Сокращённое движение | Включить `prefers-reduced-motion` | Нет анимации потока и облёта камеры, переходы мгновенные |
